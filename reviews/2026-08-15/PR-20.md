## CLAIMS

- **“DiT + VAE + condition encoder fully ported” — REFUTED.** All 21 changed Python files parse, and the classes exist, but the official `ACE-Step/Ace-Step1.5` repository has `acestep-v15-turbo/`, `vae/`, and `Qwen3-Embedding-0.6B/`; it has no `model/` weight subfolder. This PR's sole `weights_sources` entry loads `subfolder="model"`. The remote text-encoder fallback resets the path to the repository root instead of selecting `Qwen3-Embedding-0.6B`, and the required `vector_quantize_pytorch` import is neither declared in requirements nor installed in the review environment. The PR itself leaves weight-load and end-to-end tests unchecked.
- **“Pipeline registered with audio output” — CONFIRMED (static only).** `ACEStepPipeline` and its audio postprocessor are registered in the PR tree. No executable registry/load test exists.
- **“Full path, with LM stage at `cfg_scale=1.0`” — REFUTED.** There is no 5 Hz LM object, backend selector, initialization, or generation call anywhere in the ACE-Step files. The condition encoder accepts optional precomputed LM hints/codes, but the pipeline never supplies them. This is DiT-only, not the stated full path.
- **“Flow-matching Euler denoising with CFG support” — REFUTED as implemented.** The Euler loop is present. However, the trained `condition_encoder.null_condition_emb` is a loadable parameter while the pipeline creates a separate `self.null_condition_emb = None` and silently substitutes zeros for CFG. The same quiet-zero fallback is used for the required `silence_latent.pt`, which official ACE-Step loading treats as mandatory. This produces plausible-but-wrong conditioning rather than a loud load failure.
- **“Alternating full/sliding attention” — REFUTED.** `layer_types` and `sliding_window` are stored but never passed to any layer or attention call. Every DiT self-attention is full attention. The transformer also drops both latent and encoder attention masks, although the official implementation passes both; padded batched prompts can attend to padding.
- **“Pascal-reachable fallback” — REFUTED overall.** The inherited diffusion `Attention` selector does choose Torch SDPA when CUDA capability is below 8.0, so the attention-kernel sub-claim is confirmed. The required pre-Volta 5 Hz LM path is absent, though. Official ACE-Step explicitly routes capability `< 7.0` to its PyTorch (`pt`) LM backend because nano-vLLM/Triton requires Volta+. This PR instead has no LM fallback and hard-imports vLLM `ReplicatedLinear` for the DiT. It also does not thread an INT8 quantization config into those linears.
- **“Tested integration” — UNPROVEN.** PR test-plan boxes are all empty, there are no ACE-Step tests among the 24 PR files, no CI checks are attached, and no committed raw generation or quality data exists. Reviewer check: AST parsing passed for the 21 changed Python files only.

Primary comparison sources: official [GPU compatibility guide](https://github.com/ace-step/ACE-Step-1.5/blob/main/docs/en/GPU_COMPATIBILITY.md) and official [checkpoint tree](https://huggingface.co/ACE-Step/Ace-Step1.5/tree/main).

- Absent or inert: 5 Hz LM stage; `pt`/vLLM backend selection; sub-7.0 LM route; LM hints/codes wiring; usable official-checkpoint loader; mandatory silence latent; learned CFG null embedding usage; sliding-window attention; latent/encoder attention masks; INT8 wiring; ACE-Step tests; converted-checkpoint tool or fixture.
- Branch hygiene: 36 head-only commits, of which only the final three are ACE-Step commits. The PR is 451 base commits behind, includes unrelated TTS benchmarks/runtime changes, and a synthetic merge reports 11 conflicts, including registry and modify/delete conflicts in Qwen3-TTS files.

## PASCAL

**incompatible-because-no-reachable-pre-Volta-LM-fallback-and-no-honest-dtype/INT8-path.** The official checkpoint declares bfloat16; sm_61 has no bfloat16 or FP8. Torch SDPA attention selection alone does not make the integration fleet-compatible.

## NEW-FAILURE-MODES

- Official model IDs fail at missing `model/` or load the wrong text-encoder location.
- Missing quantizer dependency fails at import.
- Strict weight completeness is disabled by the loader, so randomly initialized/skipped weights can survive.
- Zero silence/null embeddings yield plausible audio with silently wrong conditioning.
- Full attention replaces trained alternating local attention, increasing memory and changing model behavior.
- Ignored padding masks contaminate batched conditioning.
- Resolving the stale branch's conflicts can resurrect obsolete TTS code or drop current registry features.

## VERDICT

**do-not-merge.** Rebase and submit only the three ACE-Step changes, then add official-layout loading with strict weight accounting, required dependency declarations, mandatory silence/null conditioning, correct masks/sliding attention, a real 5 Hz LM with automatic `< 7.0 -> pt` selection, Pascal-safe dtype/INT8 routing, and committed load/E2E/quality evidence.

**UPSTREAM: needs-split.** Correct ACE-Step support is generally useful and tracks an upstream issue, but the three relevant commits must be separated from the 33 unrelated commits. Keep portable loader/model correctness in an upstream-shaped change and isolate HT/Pascal deployment policy and evidence in the fork.
