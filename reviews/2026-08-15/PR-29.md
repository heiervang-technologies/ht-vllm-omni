# Adversarial review: PR #29 entropy guardrail

Target: `9b37aff26a13ae0b393d33004a46086d9989676d`

Reviewed against the PR base `be72432dda44c8b0cf0dbf6f095885723f24e9b5` and current `ht` tip `db0e4590b974f3fd0daecfa785614d3014336e02` on 2026-08-15. This was a serving-gem review: no GPU run and no heavy build.

## CLAIMS

- **"Monitors per-token entropy and forces EOS after sustained out-of-range entropy" — REFUTED.** `compute_logits()` first masks every invalid codec logit to `-inf` (`qwen3_tts_talker.py:453-454`), then `_apply_entropy_guardrail()` evaluates `probs * log_probs` over the full vocabulary (`:534-538`). Every masked element contributes `0 * -inf = NaN`, so the reduction is NaN. Both `NaN > threshold_high` and `NaN < threshold_low` are false; the counter resets instead of firing. The unit tests invoke `_apply_entropy_guardrail()` directly with entirely finite logits and therefore omit the production precondition that breaks the feature. A scalar IEEE-754 reproduction confirmed `0.0 * -inf` is NaN; torch was not installed on this serving host, so the submitted torch tests could not be rerun locally.
- **"Default thresholds 4.5/0.5 and window 5 detect degeneration without false positives" — UNPROVEN.** The PR commits no entropy traces, corpus, hardware identification, audio-quality labels, threshold sweep, or raw results. The only normal E2E case says a deliberately permissive 8.0/0.01 range "should NOT trigger" on one `Hello world.` prompt. It does not test the shipped defaults, singing, laughter, expressive speech, multilingual speech, long-form speech, or adversarial/reference-audio variation. The claimed rogue-deployment validation is forwarded prose, not committed measurement data.
- **"Default: server config" — REFUTED.** The API descriptions say this, but the implementation exposes only per-request fields and a hard-coded model dict. No server argument/configuration path for these defaults is added.
- **"Per-request config fixes the shared-state race" — REFUTED.** The runner calls model `preprocess()` for every batched request on every execution step, and `preprocess()` appends a config every time. `_apply_entropy_guardrail()` consumes staged entries only for token-list identities not already in `_entropy_state`. In a batch `[existing A, newly admitted B]`, staging is `[A_cfg, B_cfg]`; A consumes nothing and B receives `A_cfg`. This silently assigns another request's guardrail policy. The submitted ordered-staging test covers only two simultaneously new requests and cannot catch mixed admission.
- **"Stale entries are cleaned up by pruning" — REFUTED.** A state entry is created even for disabled requests, then `if not any_enabled: return logits` executes before pruning. With the default disabled configuration, finished-request integer keys accumulate without bound. `last_step` also stays zero for disabled state, weakening the proposed `id()`-reuse check and allowing a later request to inherit stale config if Python reuses the list address.
- **"Sentinel trailer is backwards compatible and old clients hear no perceptible artifact" — REFUTED.** Only the first eight bytes are zero. The ASCII magic, length, and JSON are emitted into `audio/pcm` as ordinary signed 16-bit samples. Encoding the PR's example metadata produced 48 samples (2.0 ms at 24 kHz), 43 non-zero samples, and a 32,053 peak (0.978 full scale). A legacy PCM client can hear a click/pop; this is plausible-but-wrong content, not a fail-loud signal. Streaming WAV receives the same out-of-band raw bytes after audio data.
- **"18 unit tests pass; E2E validates streaming and non-streaming signaling" — UNPROVEN as a result, CONFIRMED as test-body count.** The branch contains 18 unit test functions and four manual E2E functions, and all ten changed Python files parse as valid AST. GitHub reports only a successful `pre-commit` check. No committed pytest/E2E output identifies commit, hardware, model, or server image. The E2E file is a standalone script requiring a running server and local voice file; it is not evidence that CI executed it. It also forces a trigger with an intentionally impossible healthy range instead of validating real thresholds.
- **"Normal completion produces no false positives" — UNPROVEN.** The single permissive-range smoke cannot support this general claim, and the NaN defect means a no-trigger result would be indistinguishable from a disabled monitor.
- **Per-token cost is acceptable — UNPROVEN.** No before/after latency, throughput, power, or profiling data is committed. When any request is enabled, every decode step adds full-vocabulary `log_softmax`, `exp`, multiply, and reduction for the whole batch, including disabled peers, then calls `.item()` in the request loop. That introduces a device-to-host synchronization point on the token-critical path. This is especially risky on the Pascal P5200, where the only acceptable speed claims require measurement on this hardware.
- **Boundary behavior is safe — REFUTED.** Equality with either threshold is treated as healthy because comparisons are strict, while the guardrail fires when the count is exactly `window` (`>=`). The API permits `threshold_low >= threshold_high`, making almost every finite entropy out of bounds. Triggering forces EOS and returns truncated audio; clients unaware of the custom signal receive apparently successful, truncated content plus the noisy trailer.
- **Current-base integration is green — REFUTED.** The PR is three commits ahead and 501 commits behind current `ht`; GitHub marks it `CONFLICTING/DIRTY`. `git merge-tree` found nine textual conflict hunks across five files: `omni_base.py`, `serving_speech.py`, `qwen3_tts_code2wav.py`, `qwen3_tts_talker.py`, and `gpu_ar_model_runner.py`. Eight implementation files changed on both sides. In particular, current `ht` has standardized nested payload keys and newer serving/output paths that the old-branch patch does not preserve automatically.

## LOST-BODIES

Present on the PR head:

- Four request fields: enable, high threshold, low threshold, and window.
- Request-to-talker parameter forwarding.
- Talker hook, runner metadata injection, scheduler stop reason, cross-stage relay, streaming trailer, and non-streaming header symbols.
- 18 isolated unit tests and four manual E2E test functions.

Absent or not covered:

- No production-mask entropy test; this omission hides the NaN no-op.
- No stable request-ID plumbing or mixed existing/new batch admission test.
- No disabled-traffic cleanup/lifetime test.
- No validation that low threshold is less than high threshold.
- No default-threshold corpus, singing/laughter, multilingual, or long-form false-positive test.
- No raw threshold-calibration data or per-token performance/power measurement.
- No legacy-client audio-safety test for the trailer.
- No successful merge/rebase test against current `ht`; five implementation files conflict.

The feature bodies are structurally present on the stale PR head, but their joint behavior is not: the monitor cannot trigger with real masked logits, and the current-base composition is unresolved.

## PASCAL

Compatible in instruction-set terms: the patch introduces no bf16, fp8, tensor-core, FlashAttention-2, SageAttention, or cu128+ dependency. It remains operationally unvalidated on sm_61/cu126. The unmeasured full-vocabulary entropy kernels and per-token host synchronization are a Pascal-specific performance concern, not evidence of compatibility failure.

## NEW-FAILURE-MODES

- Guardrail silently never triggers because entropy is NaN after codec masking.
- Disabled-by-default serving leaks `_entropy_state` entries across completed requests.
- Mixed admission assigns one request's thresholds/enabled bit to another request.
- `id()` reuse can preserve stale disabled config because `last_step` is never advanced on the early-return path.
- Legacy PCM clients render metadata bytes as near-full-scale audio; unaware clients also accept truncated output as ordinary success.
- Invalid threshold ordering can force deterministic early truncation.
- Full-vocabulary entropy work and `.item()` synchronization can regress token latency and throughput.
- Porting the stale patch mechanically can overwrite standardized payload keys and current serving logic.
- The custom `VLLMMETA` wire trailer and public request fields become compatibility obligations once clients ship; changing the framing later is not cost-free.

## VERDICT

**do-not-merge**

Required before reconsideration: compute entropy only over finite/allowed logits with a numerically safe formulation; key config/state by real request ID and clean it deterministically; validate threshold ordering; replace the audio-payload trailer with a fail-loud transport signal; rebase and resolve current payload/serving APIs; add production-context, mixed-admission, cleanup, and legitimate-high-entropy tests; and commit named-hardware/corpus threshold plus performance raw data.

**UPSTREAM: needs-split.** A numerically safe, request-ID-keyed degeneration
guard with corpus-backed thresholds could be generally useful upstream. The
custom HT `VLLMMETA` PCM/WAV trailer is a separate wire-protocol proposal and
must not be bundled with the sampling safeguard; the stale fork integration
also needs a clean reimplementation on current upstream APIs. Dispatcher and
Markus must gate any outward submission after those concerns are separated.
